## Recent Learnings

- **Extra same-name tool calls must fail live capture scoring -> In `build_live_tool_capture_from_transcript`, require all actual tool calls to be consumed by expected-call matching, not just all expected calls to be present -> Prevents oracle-continuation turns from passing `tool_use_correct` when the model made an extra wrong call or duplicate call before the correct sequence.**
- **Oracle continuation can make real tool misses look like grader bugs -> When `tool_use_correct=false` but judge reasoning says tool use was correct, inspect `turn_runs/turn_*/tool_capture/transcript.jsonl` before blaming scorer plumbing -> The judge explains the GT-seeded oracle continuation, while `tool_use_correct` is computed from live capture, so missing/extra/wrong live tool calls on turns like 35/36/39/40/42 are real model failures with misleading judge text.**
- **Parse `audio-arena run` dirs from `Output directory:` lines only -> When scripting repeat runs, extract the run directory from the explicit `Output directory:` line instead of a broad `runs/...` regex -> Prevents accidentally capturing child artifact paths like `runs/.../transcript.jsonl` and passing an invalid directory to `audio-arena judge`.**
- **OpenAI judge schemas should list reasoning before score booleans -> In `OPENAI_JUDGE_RESPONSE_SCHEMA`, put `reasoning` immediately after `turn` in both `required` and `properties` order -> OpenAI structured outputs tend to follow schema key order, so this keeps the judge explaining itself before emitting pass/fail fields.**
- **Rehydrated OpenAI judging should fan out with bounded concurrency -> For per-turn rehydrated judge runs, issue Responses API calls in parallel behind a small semaphore such as `AUDIO_ARENA_OPENAI_JUDGE_CONCURRENCY=8` instead of strict serial awaits -> This preserves per-turn isolation and output determinism while cutting wall-clock judging time substantially on 75-turn conversation benches.**
- **`gpt-realtime-alpha-dolphin-4` was stable on conversation-bench at parallel 16 -> On March 24, 2026, synthetic `conversation_bench --rehydrate --disable-vad` repeats for `gpt-realtime-alpha-dolphin-4` completed 3/3 runs plus OpenAI judging cleanly with `AUDIO_ARENA_OPENAI_JUDGE_CONCURRENCY=8` and no salvage work -> Use this exact setup as the default first attempt for future dolphin-4 sweeps before falling back to lower run parallelism.**
- **Responses API prompt cache keys must stay under 64 characters -> When moving judges to `responses.create`, hash long cache-key components instead of concatenating full judge version/model/mode strings -> Prevents `invalid_request_error` failures from overlong `prompt_cache_key` values while keeping cache bucketing stable.**
- **Full-run OpenAI judge 400s can be transient -> If `audio-arena judge --judge openai` fails with `We could not parse the JSON body of your request`, retry the full run once before blaming a specific turn; if needed, spot-check chunked `--only-turns` subsets to confirm the datapoints are judgeable -> In the March 24, 2026 `conversation_bench` synthetic repeat batch, the first full-run judge failed once with that 400, but chunked subsets and the immediate retry both succeeded without transcript changes.**
- **Conversation-bench synthetic repeat runs at `--parallel 16` can now corrupt parent merge inputs -> If a March 24, 2026-style run fails after a timeout with `Successful rehydrated turn ... must have exactly one transcript row`, discard that attempt and rerun at `--parallel 8` instead of trying to salvage a turn dir that mixes `[EMPTY_RESPONSE ...]` and a later normal row for the same turn -> In `runs/conversation_bench/20260324T004748_gpt-realtime-1.5_c97c6809`, turn 10 wrote both an empty-response row and a successful answer while turn 60 timed out, and rerunning at `--parallel 8` produced clean `75/75` judged artifacts.**
- **Cross-turn count prompts must spell out the counting universe -> For long-memory audit turns, say explicitly whether the user wants every tool action, only successful actions, or only user-visible outcomes, and name edge categories like conflict checks, schedule additions, cancellations, and failed attempts -> Prevents turn-60-style ambiguity where the golden counts all tool calls but the user wording only names a subset.**
- **Sparse judged outputs must not crash markdown rendering -> In `write_outputs`, skip transcript rows that have no matching judgment before building the per-turn analysis section -> Rehydrated runs with runtime-excluded or missing judged turns can still produce valid `openai_judged.jsonl`/`openai_summary.json`, and the report writer should not die on a `KeyError`.**
- **Explicit tool-result payloads must be JSON-sanitized before Realtime echo-back -> In `OpenAIRealtimeLLMServiceExplicitToolResult`, sanitize `FunctionCallResultProperties` and other non-JSON-native objects before sending `function_call_output` -> Prevents `_receive_task_handler ... Object of type FunctionCallResultProperties is not JSON serializable` crashes that leave tool turns with zero-byte transcripts.**
- **Transcript recorder must sanitize tool-result metadata before JSONL writes -> In `TranscriptRecorder.write_turn`, recursively convert non-JSON-native tool-result fields such as `FunctionCallResultProperties` into JSON-friendly dicts -> Prevents post-turn transcript writes from crashing after otherwise successful rehydrated runs.**
- **Oracle continuation response grading should hide live tool capture from the LLM judge -> On rehydrated post-tool turns, omit live tool calls/results from the judge prompt, score response-quality dimensions against the oracle-seeded tool state, and populate `tool_use_correct` separately from the precomputed live-capture verdict -> Prevents contradictory live-vs-oracle artifacts from confusing post-tool response grading while still preserving deterministic tool-use scoring.**
- **Explicit runtime failures should be excluded from judged denominators -> Filter turns listed in `runtime.json.failed_turns` and transcript rows tagged `[EMPTY_RESPONSE...]` or `[NO_RESPONSE...]` out of judged summaries, but still surface them as runtime-excluded metadata -> Prevents infrastructure failures from being miscounted as model-quality misses.**
- **Multiagent synthetic fanout can create duplicate retry run dirs -> When multiple synthetic `--rehydrate --disable-vad` workers overlap on the same benchmark, select the artifact-complete run dir, salvage any zero-byte `turn_runs/*/transcript.jsonl` files into explicit `[EMPTY_RESPONSE: No valid response after max retries]` rows, then judge that stabilized parent transcript -> Prevents cross-benchmark summaries from accidentally mixing partial retries with the usable salvaged run.**
- **Tool-turn goldens should describe post-tool state, not pre-tool intent -> For oracle-continuation evals, rewrite tool-bearing `golden_text` so it reflects the answer after the scripted tool result is already known, and remove unsupported side-effect claims from closers -> Prevents benchmark contracts from expecting lines like "Let me check..." or "I'll send a confirmation" after the tool call has already been seeded.**
- **Multi-call rehydrated tool turns work best as live capture plus oracle continuation -> For realtime `required_function_call` lists, run a full live `tool_capture/` pass first, derive tool-use verdicts from that transcript, then start a fresh oracle-seeded continuation session for the final assistant answer -> This preserves whether the model actually handled fallback/error branches while keeping post-tool response grading aligned with the seeded tool state.**
- **Rehydrated parent transcripts can go stale even when all turn dirs are complete -> Before judging a salvaged repeat batch, rebuild the parent `transcript.jsonl` / `runtime.json` from `turn_runs/` with `finalize_rehydrated_run_artifacts(...)` and verify all expected turn ids are present -> In the March 20, 2026 conversation-bench juice repeat-3 rerun, several repeat 1 and 2 parent transcripts had only 69-73 rows despite 75 populated per-turn transcripts, which would have silently undercounted judged turns until the parent artifacts were rebuilt.**
- **Rehydrated no-tool turns must not continue after unexpected tool calls -> On OpenAI Realtime rehydrated turns with `required_function_call=None`, record the unexpected tool call for deterministic scoring but set `FunctionCallResultProperties(run_llm=False)` and abort before sending `function_call_output` -> Prevents benchmark-generated `UNEXPECTED_TOOL_CALL` payloads from leaking back into the model through either direct tool outputs or Pipecat's packed "previously saved conversation" context sync.**
- **Conversation-bench no-VAD can still hang at parallel 16 on juice sweeps -> If a rehydrated OpenAI Realtime run stalls with one or more zero-byte `turn_runs/*/transcript.jsonl` files even at `--parallel 16`, salvage those turns as explicit `[EMPTY_RESPONSE: No valid response after max retries]` transcript rows and finalize the parent artifacts before judging -> In the March 20, 2026 `gpt-realtime-2026-03-19-r` juice sweep, `juice=16` stalled on turn 6, `juice=64` on turns 40 and 58, and `juice=256` on turn 71 despite clean completion for the other turns.**
- **OpenAI Realtime manual turn handling must send `turn_detection: null`, not `false` -> When `--disable-vad` is enabled for OpenAI Realtime, keep `turn_detection=None` in session properties and force JSON `null` into `session.update` while still treating both `None` and legacy `False` as manual-turn mode locally -> The API now rejects boolean `false` for `session.audio.input.turn_detection` with `invalid_type`, but it accepts explicit `null` to disable turn detection.**
- **Oracle continuation judging needs an explicit source-of-truth split -> On rehydrated post-tool continuation turns, judge `tool_use_correct` from the live captured tool call/result, but judge the assistant response against the GT-seeded oracle tool call/result and label the live tool payload as capture-only -> Prevents judges from grounding post-tool answers against a truncated live `{"status":"success"}` payload instead of the canonical GT tool output.**
- **OpenAI Realtime smoke runs need explicit websocket capture for protocol diffs -> Persist sanitized `ws_events.jsonl` per turn with both outgoing and incoming event payloads when testing session-level knobs like `backdoor_options` -> The standard run artifacts show transcripts and logs, but they do not make it possible to verify whether a setting changed the actual wire payload or only local client code.**
- **Pipecat Realtime session typing drops unknown fields -> For OpenAI Realtime backdoor session knobs like `backdoor_options`, override the custom service's raw `session.update` payload instead of trying to stuff extra keys into `rt_events.SessionProperties` -> The typed model silently omits unsupported fields, so CLI plumbing alone will not reach the API.**
- **Repeat-run analysis must preserve duplicate model labels -> When `deep_error_analysis.py` is given multiple run dirs for the same model slug, append a stable run label such as run index plus `run_dir.name` before building the payload map -> Prevents same-model repeat studies from silently overwriting earlier runs and collapsing the review to the last run only.**
- **Comparison scripts need plotting deps declared in the repo env -> Keep `matplotlib` and `seaborn` in `pyproject.toml` when `scripts/compare_model_runs.py` is part of the supported workflow -> Prevents clean project environments from failing with `ModuleNotFoundError` before the benchmark batch even starts.**
- **Shared system-prompt policy changes need cross-benchmark tests -> When a behavior rule should hold across all benchmark assistants, add one regression test that checks every benchmark prompt for the required wording -> Prevents benchmark-by-benchmark prompt drift where one assistant becomes proactive or confirmation-heavy while the others silently lag behind.**
- **Offline HTML payloads must not embed pandas NaN/Infinity -> Before writing embedded JSON into `<script type="application/json">`, recursively convert non-finite numeric values to `null` and serialize with `allow_nan=False` -> Browsers reject `JSON.parse(...)` on `NaN`, which leaves the report stuck in static mode even when opened in Chrome.**
- **Conversation-bench rehydrate no-VAD hangs were frequent at parallel 32 -> If `conversation_bench --rehydrate --disable-vad` stalls with all `turn_runs/*/transcript.jsonl` present except one or more zero-byte files, salvage the stuck turns as explicit empty-response failures and rerun future repeats at `--parallel 16` -> In the March 18, 2026 gpt-realtime-1.5 audio batch, synthetic repeat 1 hung on turn 63, person2 repeat 1 hung on turn 2, and person1 repeat 2 hung on turn 52 at `--parallel 32`, while later reruns at `--parallel 16` finalized cleanly.**
- **Judge time-format mismatches should normalize 24-hour and 12-hour renderings -> In LLM judge prompts, explicitly treat times like `15:30` and `3:30 PM` as semantically equivalent, and let hydrated prior availability support fallback slot lists after `SLOT_TAKEN` errors -> Prevents appointment-bench turn 11 style false fails where the tool result uses 24-hour time but the golden/user-facing response uses 12-hour time.**
- **Avoid datapoint-shaped examples in judge prompts -> Prefer generic normalization rules over benchmark-specific inline examples that mirror real failing turns -> Prevents overfitting the grader to known datapoints and keeps prompt guidance policy-level rather than case-level.**
- **Multiagent realtime evals need an API-key preflight -> Check `OPENAI_API_KEY` in the parent shell before spawning benchmark workers, and fail fast if it is absent -> Prevents a full multiagent batch from producing only 0-row transcripts plus `No turns to judge`, as happened for all six benchmarks on March 18, 2026.**
- **Repo analysis scripts require pandas and the local `.venv` may lack `pip` -> Bootstrap with `.venv/bin/python -m ensurepip --upgrade`, install `pandas`, and keep `pyproject.toml` declaring it -> Restores `deep_error_analysis.py` and other checked-in analysis scripts that import pandas, and avoids rediscovering that this venv can exist without pip.**
- **Rehydrated no-VAD runs can hang on a single turn with a zero-byte transcript -> When all other `turn_runs/` are complete but one `transcript.jsonl` is size 0 and still streaming in `run.log`, finalize the parent run by treating that turn as an explicit failed/empty-response row instead of dropping it or waiting indefinitely -> Preserves a 75-turn judged artifact set and makes the runtime failure visible in `failed_turns`, as seen on conversation-bench synthetic turn 67 and real-audio person1 turn 36 on March 18, 2026.**
- **Multi-call turn specs need list-shaped responses on every affected turn -> When `required_function_call` is a list, keep `function_call_response` as a same-length list and add a regression assertion over the concrete benchmark turns that use multi-call updates -> Prevents harness-level `scripted tool responses are inconsistent` failures from benchmark data shape drift, as seen in `appointment_bench` turn 21.**
- **Deep error analysis packet filenames collide across parallel benchmark workers -> When running `.agents/skills/model-run-error-analysis/scripts/deep_error_analysis.py` in parallel, copy `results/failure_review_rows.csv` and `results/failure_review_rows.jsonl` to benchmark-and-run-specific filenames immediately after each invocation -> The helper script honors a unique markdown `--output` path but still writes shared packet filenames, so concurrent analyses can overwrite one another.**
- **Rehydrated judge prompts should use golden prior history, not prior transcript outputs -> When judging `--rehydrate` runs, feed the judge a hydrated golden-history section plus current-turn actual outputs, and explicitly forbid using one target turn's actual block as state for another -> Prevents late long-range-memory turns from inheriting earlier real transcript tool failures that should be overridden by golden prior context.**
- **Prompt-visible catalog names plus hidden tool-only details is a cleaner grocery contract -> Expose a names-only product index and confusable-name hints in the grocery system prompt, but keep prices, sizes, and item IDs tool-only; then tell the judge to score pre-tool claims against the prompt-visible KB and post-tool claims against tool results/full KB -> This keeps the model aware of what exists without letting it answer catalog-detail questions from prompt memory, and it prevents bouquet-style grounding penalties based on hidden catalog rows.**
- **Conversation-bench rehydrate can false-fail late state summaries by using model history instead of golden prior context -> On `conversation_bench --rehydrate` runs, manually verify long-range-memory summary turns against `turns.py` goldens when the judge says prior registrations/actions never happened -> In the March 12, 2026 run `runs/conversation_bench/20260311T235158_gpt-realtime-1.5_a3ca59b7`, turns 52/56/57/58 matched the benchmark goldens but were judged from earlier model-side tool misses despite `runtime.json` noting "golden prior context" per turn.**
- **Appointment-bench parallel-32 rehydrate no-VAD can still be artifact-clean -> Treat `appointment_bench` runs with `--rehydrate --disable-vad --parallel 32` as scoreable when transcript/judged coverage stays `25/25` and `turn_taking_failures=[]`, then focus review on content errors rather than assuming concurrency-induced runtime corruption -> In the March 11, 2026 run `runs/appointment_bench/20260311T235157_gpt-realtime-1.5_2251e121`, the artifacts were clean and the remaining misses were turn 3's non-responsive post-tool utterance and turn 17's premature `end_session`.**
- **Judge grounding leniency needs concrete examples, not just abstract guidance -> If a recurring false fail comes from harmless present-tense commentary, add an explicit benchmark-shaped example to the judge prompt instead of only saying "be generous" -> In grocery-bench, abstract leniency rules did not clear turn 8 until the prompt explicitly said same-day-delivery follow-up language like "we should be good" should pass absent contrary time evidence.**
- **Prompt-filtered grocery KB shifts failures from fake tool misses to real follow-up issues -> After removing catalog facts from the grocery system prompt, first-discovery turns started calling `lookup_item` reliably, and the remaining judged misses clustered around over-clarifying quantity defaults, one unsupported same-day timing claim, and late-order edit/state mistakes -> Use the prompt-filtered setup when you want grocery-bench to measure actual retrieval plus workflow behavior instead of prompt-memory compliance.**
- **Prompt-facing KB should not include tool-retrievable catalog facts -> In grocery-bench, keep delivery/store-policy sections in `system_instruction` but strip product catalog and confusable-item tables from the prompt-facing KB -> Prevents first-discovery item turns from being answerable out of prompt memory while still allowing direct answers for store-policy questions.**
- **Judge CLI can silently drop benchmark KB context -> Always pass `knowledge_base.txt` into OpenAI/Claude judge calls, not just expected turns and system prompt fragments -> Prevents KB-grounding false fails where the judge treats benchmark facts as unsupported because they never reached the model prompt.**
- **Grocery-bench turn 8 same-day-delivery answers can be falsely marked ungrounded -> When `openai-v4-rehydrated-tool-results-in-prompt` returns `kb_grounding=false` on turn 8, verify `benchmarks/grocery_bench/data/knowledge_base.txt` before treating it as a model hallucination -> In the March 11, 2026 run `runs/grocery_bench/20260311T165504_gpt-realtime-1.5_a14b9360`, the assistant's "before 2 PM" and "2-4 hour window" answer matched the KB exactly, so the miss was judge-side or prompt-packaging-related rather than a real grounding failure.**
- **`--skip-turn-taking` still renders all-pass turn-taking summaries -> Treat `openai_summary.json` / judge console `turn_taking=25/25` on skip-turn-taking runs as a display artifact and rely on the flag plus `turn_taking_failures=[]`, not the pass count, when deciding whether turn-taking was actually evaluated -> Prevents rehydrated no-VAD reviews from accidentally treating forced-pass turn-taking fields as meaningful metrics.**
- **Tool-use scoring needs explicit first-discovery vs state-reuse guidance -> Add per-turn `tool_use_guidance` and surface it in the judge prompt so lookup-required catalog introductions stay strict while later turns can reuse already-established item facts without redundant lookups -> Prevents grocery-style evals from penalizing efficient session-state reuse and makes the intended contract legible to the judge.**
- **Realtime tool continuation needs two server-side gates -> Wait for both `conversation.item.added`/`conversation.item.done` on the injected `function_call_output` item and the prior `response.done` before sending deferred `response.create` -> Prevents missing a fast tool-output ack or fast response completion while the websocket send is still in flight, which can otherwise leave the continuation racing stale conversation state.**
- **Appointment-bench LLMAJ KB false fails are not stable under repeated replay -> When `gpt-5.2` marks appointment-bench turns 9 or 23 as `kb_grounding=false`, verify with repeated same-prompt replays before changing GT or prompt wording -> In a March 11, 2026 experiment on run `runs/appointment_bench/20260311T100636_gpt-realtime-1.5_448966ba`, replaying the current rehydrated LLMAJ prompt for turns 9 and 23 10 times at `reasoning_effort=none` and 10 times at `low` produced `kb_grounding=true` on 20/20 runs for both turns; `low` occasionally added a separate turn-23 completeness/state penalty, but never reproduced the original grounding miss.**
- **Rehydrated runtime summaries can overstate completion after a failed final turn -> Verify `transcript.jsonl` and judged-row coverage even when `runtime.json` says `failed_turns=[]` and all turns succeeded -> In the March 11, 2026 run `runs/event_bench/20260311T100636_gpt-realtime-1.5_0ba2711a`, `runtime.json` reported 29/29 success, but `transcript.jsonl` and `openai_judged.jsonl` stopped at turn 27 after turn 28 hit `no close frame received`, `Error connecting: [Errno 8] nodename nor servname provided, or not known`, and `session was not ready before rehydration seeding`.**
- **Rehydrated reconnect fallback must preserve tool results -> Mirror `function_call_response` payloads into reconnect history and render them back into the fallback prompt -> Prevents fresh-session retries from losing benchmark state after websocket reconnects.**
- **Grocery-bench rehydrate can complete cleanly while failures stay mostly model-side -> Treat `grocery_bench --rehydrate --disable-vad` runs with full `30/30` transcript coverage, `30/30` judged rows, and `turn_taking_failures=[]` as scoreable, then bucket remaining `gpt-realtime-1.5` misses into missed lookup/tool-completeness turns, pre-order state confusion, and post-order edit mistakes instead of runtime artifacts -> In the March 11, 2026 run `runs/grocery_bench/20260311T100643_gpt-realtime-1.5_364e7750`, the artifacts were clean, but turns 2/5/17/20/23 missed required lookup completeness, turn 19 wrongly claimed it could not edit the in-progress order yet, and turns 26-27 mishandled the post-order modification logic.**
- **Manual no-VAD retries need explicit state reset -> Clear OpenAI Realtime manual commit/response flags before replaying a turn's audio on retry -> Prevents retried `--disable-vad` turns from being dropped and mis-scored as model failures because duplicate stop events are ignored.**
- **Appointment-bench rehydrate skip-turn-taking needs manual bucket correction -> On `appointment_bench` rehydrated `gpt-realtime-1.5` runs, treat raw `kb_grounding` fails on turns 9 and 23 as likely judge grounding mistakes and subtract the expected closing `end_session` turn before interpreting `MODEL_ENDED_SESSION` counts -> In the March 11, 2026 run `runs/appointment_bench/20260311T100636_gpt-realtime-1.5_448966ba`, the artifacts were clean `25/25`, all required tool turns were on time, the only clear real model errors were turn 1's missed Thursday schedule constraint and turn 17's premature session close, while turns 2/9/23 were better explained by strictness or judge-side grounding issues.**
- **Event-bench quote and availability turns can under-answer despite same-turn tool results -> Turns 1, 6, 9, 14, 20, and 23 stop at "let me check/get a quote" even though `function_call_response` already contains the venue/price answer and later user turns presuppose that answer -> Treat these turns as GT issues before blaming models that answer the quote or availability directly.**
- **Some closing goldens add unsupported post-close narration -> `conversation_bench` turn 74 invites more help after `end_session`, and `event_bench` turn 28 plus `grocery_bench` turn 29 add confirmation-sending claims with no supporting tool or KB evidence -> Do not treat those extras as required behavior when triaging end-of-conversation failures.**
